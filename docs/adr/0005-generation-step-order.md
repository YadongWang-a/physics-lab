# 生成流程步骤链：分析题目 → 物理模型 → 解答与答案核对 → 临界状态 → 物理量 → 图像 → 落地

`physics-skill-prompt.ts` 内嵌的 skill 规范按"先建模型、再推导、后落地"重排为 7 步：① 分析题目 ② 物理模型（展示维度 2D/3D + 元素与位置关系 + 结构件初始状态，产出假设清单）③ 解答与答案核对（推导先行且可见输出，推导完成后向用户索取官方答案并**停下等待**）④ 临界状态（硬判据 = ③ 的阶段划分）⑤ 物理量（产出「物理量表」：量名 / 计算式 / 是否临界前后两值 / 承载通道 / 矢量分解合成画法）⑥ 图像（判据 = 过程有阶段性变化且能回答一句讲题问题）⑦ 落地（命名 → 模板填空 → `check_demo` 自检）。命名与 lib 确认不再单列步骤：命名并入 ⑦，lib 预置与缺失补拷改由应用层系统提示声明（`agent-runner.ts` 的 `skillSystemPrompt`）。

**Status**: accepted

**Considered Options**:
- **原结构（§2 澄清几何 / §3 推导与答案确认 / §4 命名 / §5 确认 lib / §6 生成 HTML / §7 自检）** —— 几何先于推导的顺序本来就是对的，但"展示维度、元素与位置关系、物理量、图像"四类设计决策没有落点（散在 §6 与「内容规则」里），而命名与 lib 这类工程落地细节却占了与讲题分析同级的步骤位
- **按草稿顺序（分析题目 → 找答案 → 讲题思路 → 模型/2D-3D → 元素与位置关系 → 临界状态 → 物理量 → 图像）** —— 否决：循环依赖。位置关系未定时答案可能不唯一（「反着摆」判据正是为这类题设的），且推导开头的假设清单（几何顺序、结构件初始状态、绳长）本身就是"元素与位置关系"的产物；把模型放在推导之后，推导只能在未知几何上展开
- **答案先行（原 §3「先索取答案/解析…避免整版返工」）** —— 否决：答案先进入上下文会让模型照着答案凑推导，推导失去"被审、被自复核"的意义；改为推导先行、完成后再索取并核对，不一致就停下问用户
- **保留"几何提问与答案索取同一轮消息"** —— 随顺序调整自然失效（几何问在 ②、答案索取在 ③ 末），接受多一轮往返，换来推导不被答案锚定
- **设计产物（元素表 / 物理量表 / 图像判据）全部写给用户确认** —— 否决：每道题多两张表与一轮确认，与"对话式驱动"冲突；设计产物内部留存，结果在演示里自明（seg / hud / 图表 / 读数）
- **2D/3D 按"讲解效果"由模型自选** —— 否决：3D 路径在仓库内零样例（`resources/demos/` 10 个演示全 2D），写入成本也更高（屏幕空间绘制、每个元素经 `w2s` 投影、拖拽被旋转接管）；改为默认 2D，只有能指出"哪个约束非三维不可"才用 3D
- **步骤引用改用节名** —— 否决：提示词内部同文件引用编号最省 token 且可 grep；改为外部文件（`agent-runner.ts`、`check-demo/tool.ts`、`check-demo/static-check.ts`）一律用语义描述，不再提步骤号
- **改已有演示按改动类型分级跳步** —— 否决：分级要求模型先判定改动类别，新增判据与失败面；保持"只跳命名与 lib 准备，读文件后编辑"

**Consequences**:
- 步骤号是提示词内部约定，改动须同步提示词内的交叉引用；仓库其他文件不再出现步骤号
- 「内容规则」的受力分析构造与速度矢量降级为被引用的画法细则（画哪些量、是否分解/合成由 ⑤ 决定）；状态切换只保留渲染与交互语义（时刻表由 ④ 给出，判决量与滑块边界移入 ⑤）
- 已接受的代价：改已有演示保持粗粒度 → 对"仅改滑块默认值"可能重跑推导与临界分析；几何含糊的题多一轮往返；`-3d` 命名约定（与同题 2D 版并存）不变
- 本次验收为 `npm test` + `typecheck` + `--smoke-checkdemo`（不真跑模型）：新链条是否被模型遵守未在本轮验证，单测只能锁定提示词文本契约
- 正文只留可执行规则与判据，**理由不进正文**：「推导可见＝被审、被自复核的依据」记于此，「hud 是投影唯一通道的理由」记于 ADR-0004，「整读 `lib/common.js` 的代价」记于 ADR-0003 修订；画布文字通道的**示例**下沉到 `drawing.md` §6（该处原本只是"与 SKILL「内容规则」同源"的复述，现改为唯一真相源）

## 修订（2026-10-02）：取消「无答案时索取答案并停下等待」

本文首段「③ 解答与答案核对（……推导完成后向用户索取官方答案并**停下等待**）」与 Considered Options 中「保留推导先行、完成后再索取并核对」的口径据此修订：**题面/用户未给答案时不问、不停**。

依证据：工作目录 `.pi-sessions/` 的 4 个真实会话中，4/4 都出现用户回复「没有答案(按你的推导)」，出现「有答案」的次数为 0 —— 这个闸门 100% 概率换来一轮空往返，而它保护的路径（官方答案核对）从未被使用。

**Status**: accepted

**Considered Options**:
- **保留闸门** —— 否决：4/4 会话白付一轮；软闸门在本仓库有前科（ADR-0007 记「实测五段闸门 0/4 触发」）
- **问但不停**（仍输出 `[选项] 有答案 | 没有答案`）—— 否决：按钮＝邀请回答，老师会以为必须点，正是要消掉的那一轮
- **问、停、应用层自动继续** —— 否决：往返次数没变，等于没解决
- **页面留痕**（判定卡/答案节标「按推导」）—— 否决：演示 HTML 是会被拷走、长期留存、投影给学生看的产物，「未经核对」字样对老师是负资产；且事后拿到官方答案时旧字样会残留。告知职责放在对话里
- **连「假设清单需用户确认」等题面信息不足的提问一并删除** —— 否决：那些是模型无法自决的硬前提（位置关系、结构件初始状态、题面矛盾），与流程礼节不同性质
- **新开一篇 ADR** —— 否决：闸门属于本文的步骤链决策，拆两篇会让同一条链的表述漂移（`0003`/`0007` 均就地追加修订）

**Consequences**:
- 失去「落地前的人工拦截点」：推导若有错，纠错发生在页面落地之后（「不一致改页面、不改推导」不变）。实测用户本就事后纠错（如「你这个磁场方向对吗？」），代价可接受
- §3 完成条件与 §7 落盘链不再引用「对答案」：`§1 建文件 → §2 基本模型 → §3 解析卡 → §4-§6 补 seg/hud/矢量/图表`
- 只删答案闸门：§2 几何/初始状态提问、题面矛盾纠正、§3 假设清单确认、重名提问、给答案后的冲突停下全部保留
- 节名仍为「解答与答案核对」：用户补上答案即核对这条真实路径还在
- 验收：`test/skill-prompt.test.ts` 锁新文本契约（断言不再含「停下等待」与 `[选项] 有答案`）＋ `typecheck` ＋ 真跑一次无答案题确认同轮落地

## 修订（2026-10-04）：生成拆两轮，分析轮止轮等确认

本文首段「③ 解答与答案核对（推导先行且可见输出…）」与 2026-10-02 修订（取消「无答案时索取答案并停下等待」）据此再修订：**新建演示默认拆两轮**——① **分析轮**（§1→§3）把模型假设与推导作为**可见文本**输出后**止轮等确认**；② **落地轮**（用户确认后）一次补齐全部产物。**豁免**（不拆、单轮 §1→§7）：输入是物理过程、题面/用户已给答案、用户要求直接生成、用户已确认过推导。

恢复的不是「索取答案」闸门（2026-10-02 的决定继续有效，`[选项] 有答案` 不再出现），而是「推导确认」闸门——目的在延迟，不在答案。

依证据（`.scratch/physics-lab-desktop-app/issues/11-generation-latency.md` 与 `.scratch/perf/`）：

- 步 1 的 **54k（会话 A）/ 85k（会话 B）reasoning 令牌发生在第一个工具调用之前**，上下文仅 ~6k——模型在隐藏 thinking 里把整道题算完；该回合可见文本 2,666 字 ↔ 隐藏 thinking **438,762 字（164×）**。
- §3 的「推导先行且输出给用户」**未被遵守**（可见输出 91 字、未等确认就写了文件）——旧形态下这条是付费的 no-op。
- 同一份推导在步 8（120,209 字 / 169.7s）、步 9（62,698 字 / 102.6s）**反复重算**；reasoning 会被回灌成后续每步输入（`requiresReasoningContentOnAssistantMessages`），早期多想的 1k 在后面每一步复利。

**Considered Options**:
- **分析轮不落任何文件**（issue 11 P0 原稿「不得同回合写文件」）—— 否决：与 ADR-0007「先落文件、早预览」冲突，且骨架不含物理内容、无返工风险；改为「分析轮唯一落盘 = 骨架」
- **保留旧形态（推导不强制可见、不等确认直接落地）** —— 否决：推导不进可见文本，隐藏 reasoning 无从约束
- **沿用 `[选项] 有答案` 那种闸门** —— 区别明确：旧闸门索取的是**信息**（4/4 会话答「没有答案」，100% 空转），新闸门索取的是**判决**（推导对不对）

**Consequences**:
- 每道题多一次用户交互（一次点击）；换来分析轮的隐藏 reasoning 压到可见文本 + 后续步骤不再重复推导
- §3 完成条件不再含「解析卡已落盘」：解析卡改由 §7 落地轮一次补齐（见 ADR-0007 修订）
- `test/skill-prompt.test.ts` 的 `not.toContain('停下等待')` 删除，改为正向断言两轮与止轮；CONTEXT.md「题目」条目同步
- **收益未单独 A/B 实测**：本批还含单源化 / 一次补齐 / 核对工具化（ADR-0010、ADR-0007 修订），无法单独归因；验收方法见 issue 11 的 P5 与 `.scratch/perf/timeline.mjs`

## 修订（2026-10-05）：新增「纯解答/纯问答」分支（只给答案，不做演示）

新增一条分支: 用户说「只给答案 / 只要答案 / 先别做演示 / 只讲解答 / 不用做演示」(或问结论、核对选项、讨论) → **一轮内只读题推导、给答案**，不建文件、不产出任何演示产物；§3 只保留 假设清单 / 推导(可见文本) / 对答案 / 公式格式，§2 的落位、§5、§6、[内容规则]、图清单与讲解点、状态 seg、§7 全部、两轮与 `[选项]` 确认一律不适用。§1 的「可运行的空页面已写入」闸门同步限定为**新建演示**专属。

理由有两条：

1. **诊断**：长思考的成因未定（题目本身的几何搜索 vs 演示制作要求）。同一 system prompt 下只换交付物，可把两个变量分开——若纯解答仍烧掉十几万推理令牌，则成因在题目；若骤降，则成因在制作。
2. **产品**：老师常常只要一句答案，不需要每次都建演示。

**Status**: accepted

**Considered Options**:
- **新增独立提示词变体**（另一份常量）—— 否决：违反 ADR-0010 的单源化，两份正文必然漂移
- **沿用旧「纯问答/确认」措辞**（只走 §3, 不写文件）—— 否决：§3 本身含图清单/讲解点/止轮，会把演示规划带进思考；必须显式列「不适用」
- **在纯解答里也加收敛约束**（如"否决两次即提问"）—— 本轮不加：会把诊断变量又混进来

**Consequences**:
- 触发靠用户措辞，模型自行选路；若误判（把"只给答案"当成新建演示）则诊断失效——首次实测时需人工确认它没建文件
- `test/skill-prompt.test.ts` 增加该分支的文本契约

## 修订（2026-10-05 第二版）：解题封闭并冻结，演示只搬运（S0/S1/S2）

起因是一次同题 A/B（第 15 题第(2)问；诊断数据见 issue 11 与 `.scratch/perf/`）：

| | 「制作第二小题」 | 「解答第二小题」 |
| --- | --- | --- |
| 墙钟 / 请求 | 696.4s / 1 | 129.6s / 1（正常 `stop`） |
| 推理令牌 | 170,833 | 28,526 |
| thinking 字符 | 494,735 | 88,432 |
| ✗ 否决候选 | 170 | 2 |

同题、同日、同一 system prompt，只换交付物 → 6 倍推理、85 倍否决，且制作那次不收敛。主题密度对比显示两次运行**做的是同一类物理推理**（物理推导 40.2 vs 40.0 命中/万字符，自洽核对 11.0 vs 11.9），生成类词汇两次都≈0（1.7 vs 1.1/万字符），且制作块里的生成规划集中在 **97–99.5% 处**（`animat` 96.7%、`hud` 97.1%、`图清单`/`讲解点` 97.3%）。结论：**不是"边解边画"的穿插，而是"制作"这个交付物拿掉了唯一的终止信号**——模型把"得出答案"换成了"得到一套完整自洽、样样能摆进画面的构型"。

因此把一次生成切成三段，并给解题段一个**可判定的终点**：

- **S0 骨架**（解题轮开头）：可运行空页面。判据 = 文件已写入。
- **S1 解题**（解题轮）：只按**题面所问**推导。判据 = **题面所问的结论已写出**。三条边界规则：① 题面未问的要素（画面里出现但推导用不到，如加速管如何提供初速）写一行「未涉及」，不展开；② 同一假设被自己否决两次 → 停，把候选/冲突/缺口写成问题问用户；③ **结论冻结**，后续任何阶段不得改动。
- **S2 投影**（演示轮）：只搬运冻结结论；缺量一步代数导出，导不出标「待补」（详见 ADR-0007 修订）。

同时收窄两条开放判据：§2 由「元素与位置关系、结构件初始状态**已唯一确定**」改为「**推导所需**的已定」；§3 由「**覆盖各阶段**守恒律与事件判据」改为「只覆盖题面所问所必需」。

**Considered Options**:
- **只加「否决两次即停」** —— 不够：那只治枚举，不治"判据开放"本身（§2 唯一确定 / §3 覆盖各阶段仍在）
- **S1 封口判据取「题面所问 + 演示最小所需清单」** —— 否决：等于把 S2 的需求提前塞回 S1，膨胀风险原样回来（若实测「待补」过多再退到此档）
- **拆成三次交互（骨架轮 / 解题轮 / 演示轮）** —— 否决：骨架不需要用户参与，交互次数维持两次
- **保留「分析轮 / 落地轮」命名** —— 否决：名字与实际职责不符；改「解题轮 / 演示轮」让冻结边界写进词本身（CONTEXT.md 已同步）

**Consequences**:
- 封口 / 冻结 / 两次否决都是**可判定的句子**，可用会话 trace 机械核验（✗ 计数、是否出现未问子问题的搜索）；统计脚本 `\.scratch/perf/reasoning-stats.mjs`
- 预期指标（同题 A/B）：S1 推理令牌向纯解答实测的 28.5k 靠拢（而非 170.8k）；✗ 从 170 降到个位数；S2 内不出现未问子问题的搜索
- **风险与未验**：封口可能让演示缺料（表现为大量「待补」）；本轮改动尚未做真机 A/B
- `test/skill-prompt.test.ts` 增「封口 / 冻结 / 只搬运」契约，并断言两条旧开放判据不再出现

## 修订（2026-10-05 第三版）：取消确认闸门——不问、不停

本文 2026-10-05 修订的「解题轮 → 止轮等确认 → 落地轮」据此改为**一个回合内走完**：解题段（S0 骨架 + S1 解题）写完可见推导与结论后**接着**走 §4→§7，不再输出 `[选项] 按此推导落地 | 我要改`、不再止轮。S0/S1/S2 的分段与全部边界规则（封口判据、题面未问要素标「未涉及」、同一假设否决两次即停、结论冻结、演示段只搬运）保留。

理由：

- 治搜索爆炸的是**封口判据 + 结论冻结 + 演示段只搬运**，不是确认闸门；止轮只多一次交互，且当时没有任何实测支持它降本（提出后首次真机运行在 402 之前只发出 1 个请求，闸门从未被触发）。
- 与本文 2026-10-02 修订（不问、不停）同向：那次否决的是「索取答案」闸门，本次把「确认推导」闸门一并去掉——两者都是礼节性往返，不是模型无法自决的硬前提。
- 保留的提问面：题面信息不足、文字与物理矛盾、位置关系未指明、重名等**硬前提**仍按 §2 提问。

**Consequences**:
- `[选项]` 机制本身保留（g 取 9.8 / 10 这类真实选择仍可用），只去掉"确认推导"那一处
- 命名随之改：解题轮 / 演示轮 → **解题段 / 演示段**——它们是同一条消息内的两段，不是两次用户往返（CONTEXT.md 已同步）
- `test/skill-prompt.test.ts` 断言：含「一个回合内走完 §1→§7」「推导可见且不中断」，且不含「止轮」与 `[选项] 按此推导落地`
- **弱化点**：推导「必须可见」失去止轮这个强制点，退回软约束（2026-10-02 之前它被违反过：可见 91 字 vs 隐藏 thinking 438k 字）。留观：若真实运行里推导再次只出现在隐藏思考，改用非交互手段（如应用层在首个工具调用前插一个纯文本回合），而不是重新引入用户往返

## 修订（2026-10-07）：改已有演示优先于 `-3d` 命名约定（会话内修改一律原地）

现象（真机）：在 `u-frame-spring-magnetic-drag.html` 的会话里说「改成3d模式」，模型**新建**了 `u-frame-spring-magnetic-drag-3d.html`，并在回复里声明「2D 版保留未动」。

原因是提示词里两条规则打架：「分支·改已有演示 → **文件名不变**」对上「§2 展示维度 / §7 步骤 1 → 3D 用 **`-3d` 后缀命名**」；用户改了维度，两条规则给出相反的文件名，模型选了命名那条——而 `-3d` 后缀的原设计意图（本文 Consequences）本就是「与同题 2D 版**并存**」。

**并存意图与 ADR-0002（一个 HTML 一个会话）冲突**：会话绑定文件，用户在会话里说「改/换」时期待的是这个文件变。实测后果已经坐实：应用按 stem 把新文件登记为 `u-frame-spring-magnetic-drag-3d.jsonl`，而该会话文件并不存在（真正的对话在 `_new-1791341232297-wlggco.jsonl`）——点开那个 3D 演示是一个空会话，历史断链。

修订：**`-3d` 后缀只约束新建演示**；改已有演示（含换维度、整页重做）**一律原地改、文件名不变**，换 3D 就地换成 `template-3d.html` 骨架。

**Considered Options**:
- **换 3D 时把文件重命名成 `-3d`** —— 否决：会话文件按 stem 命名（`resolveSessionFile`），重命名会打断 html↔会话绑定，要应用层联动改名，收益只是"名字好看"
- **保留并存（现状）** —— 否决：与 ADR-0002 冲突，且用户明确要求「在本文件中完成」
- **新建后自动把会话迁到新文件** —— 否决：把模型的一次选择变成应用层的会话搬迁，代价远大于收益

**Consequences**:
- 由 2D 就地改成 3D 的演示，文件名**不带** `-3d`——后缀不再保证"这个名字就是 3D"；判 3D 要看内容（`template-3d` 特征），这也与 ADR-0008 的"显示名 ≠ 身份"一致
- `test/skill-prompt.test.ts` 增加契约：改已有演示含「换维度 2D↔3D」且「不另建 `-3d` 文件、不改名」

## 修订（2026-10-07）：3D 取景判据（`drawing.md` §11）

**现象**：3D 版（`u-frame-spring-magnetic-drag-3d.html`）观感差。把它真打开量了一次（浏览器渲染 + 画布像素统计）：

| 指标 | 3D 版 | 同题 2D 版（同画布 1015×500） |
| --- | --- | --- |
| 内容包围盒 | 751 × 140 px | 882 × 233 px |
| 占画布高 | **28%** | 47% |
| 投影后宽高比 | **5.3 : 1** | 3.8 : 1 |

**根因**：取景盒 `x∈[-1.2, 10.8]`（12 单位）是高的 5.3 倍，视口 fit 取 `min(sx,sy)` → 被**宽度**卡死，高度只用到 28%，上下各空约 180px。连带 3D 的卖点失效：题目核心是「竖直向上的 B 场」，但 y 向只有 1.1、箭头用灰色 `#9aa2b1` 与桌面同色系，`el=0.90` 下竖直贡献又被桌面深度与超长 x 抢走。

**为什么模型会这么画**：`drawing.md §11` 原本只有相机与投影 API，**没有任何取景判据**（世界盒比例、内容占画布比、竖直量长度、标注避让）；而 `resources/demos/` 十个演示**全是 2D**（本文 Consequences 已记「3D 零样例」）。

**改动**：§11 新增「取景与观感」——世界盒与画布相称（投影后宽高比 1.5~2.5:1）、长导轨用**截断**表示「足够长」、竖直量长度 ≥ 画面高 8% 且**高对比色**、默认 `el` 0.8~1.1、标注避让；并附一条可粘贴进 `check_demo` 的 `assertions` 收尾自查（内容包围盒高度 ≥ 画布高 50%）。提示词 §7 核对第 3 项加 3D 指针。

**Considered Options**:
- **补一个 3D 参考样例**（把现有 2D 演示手工转 3D 入库）—— 本轮未做：工作量大，先把判据立起来
- **把取景检查做进 `check_demo` 的运行时检查**（自动、不依赖模型记得传断言）—— 未做：沿用「可机械化项交给 `check_demo`，但由调用方传 `assertions`」的既有分工；若实测模型不传，再升为内建检查
- **阈值 50%** —— 取实测坏例子（28%）与合格对照（90%）之间；2D 版实测 47%，故本判据**只约束 3D**

**Consequences**:
- 取景断言已实测：坏例子 → `false`，人为构造的合格取景（高度 90%）→ `true`
- 未解决：`el` 默认值与三视图预设的关系、标注避让仍靠模型自觉（无机械检查）
