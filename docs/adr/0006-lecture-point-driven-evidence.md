# 讲解点：物理量、图像、图例的取舍都由"讲解"驱动

演示 HTML 的目标是辅助讲题，所以 §5 物理量、§6 图像、图例三处的判据改为挂在同一个 **讲解点** 上。**讲解点** = 老师在课堂上要讲出口的一句话结论，来源被钉死在 §3 的产出（每个阶段结论、每个选项的判决），因此是闭合可枚举的集合。规则是**双向全覆盖**：

- 正向：每个讲解点都必须在画面上能被指认（量 / 矢量 / 曲线 / 图例层），且证据落在**投影可见面**内（画布 + `.phase` + `.legendbar` + `.charts-row` + `.scene-hud`，定义见 ADR-0004）——侧栏 `.ro` 读数在演示模式整栏隐藏，不能作为某个讲解点的唯一证据。
- 反向：没有讲解点的量、矢量、图、图例项不出现。

§5 的产物由「物理量表」改名为「**讲解点证据表**」（首列是讲解点，不是量名）；§6 的图必须在其 `title` 写明它回答哪个讲解点；图例被定义为画布视觉编码的**唯一解码入口**（每个用来区分含义的编码归属一个 legend 层，层 label 即含义、可单独开关）。

**Status**: accepted

**Considered Options**:
- **现状（按"来源"列量 + 图"能回答一个讲题问题"）** —— 否决：`讲解需要` 不可判，模型按"有哪些量"平铺，或按来源凑数；图是单向判据（图→问题），没说哪个讲解点必须有图；图例在提示词里只有禁止侧（颜色说明→图例）、没有正向规格
- **写死数量预算（hud ≤4、图 ≤2、图例 ≤5）** —— 本轮否决：数量预算能机械检查，但会把手伸进教学判断（一张图讲的清楚的题不该被允许或少给）；改由双向全覆盖承担取舍，代价是投影拥挤风险退回自检、不可机械查
- **扩 lib 能力后再写措辞**（`setupCharts` 加 `marks` 标讲解点时刻、`legend` 支持无 `k` 的纯颜色键、`SC.hud` 支持随状态 seg 切换）—— 本轮否决：先只改提示词；为不制造不可执行规则，措辞规避了这三处：时刻由状态 seg 定格（图只负责趋势与转折）、解码用"每个编码归属一个可开关的 legend 层"实现、hud 超编用取舍优先级（选项判决量 > 临界前后两值 > 初始条件量 > 其余）落到画布矢量/解析卡
- **让模型自列"讲解点 → 证据"对照表并输出给用户** —— 否决：设计产物内部留存（与 §5 一致），结果体现在演示里

**Consequences**:
- **图清单（推导 → 表示 → 核对）**：§3 推导末把"用到的每个元素与条件"转成逐行的**表示清单**（列：推导元素 / 表示 / 服务讲解点 / 通道 / 已落盘），§5 逐行为它定通道与取值，§7 核对项逐行清零，收尾用一句话按清单向老师汇报。它是"要画什么"的唯一真相源（不再另起"证据表"）
- **核对工具化**：`check_demo` 增加 `drawList` 参数（`{kind, text?}`，kind 闭集：vector/component/cone/hud/chart/seg/label）→ 缺行报 **error**（触发应用层修复循环），只核**存在性/计数/文本**；闭合是否正确、抵消方向是否真属语义，仍靠 §7 自检。**不新增工具**（ADR-0003 工具面最小化：渲染类工具与 lib 标准件重复，无增益）
- 已知未落地通道：**力多边形插图**（`.charts-row` 只支持曲线；场景内画会遮挡几何）与**判据条**（算式/不等式在投影面无处可放）——图清单中相应行必须标「待补」，不得假装已落盘；二者属后续 lib 改动（判据条 / `setupVectorInset`）
- **精简实验结论（同日）**：把 `内容规则` 整节（54 行，提示词 10178→8132 字符，−20.1%）移出常驻后，速度**无收益**（首个 write 491 s vs 463 s；回合 629 s vs 495 s；工具 28 vs 18），且 `angleArc` 归零——"凡有角度→必画角度弧线"这类规则**没有别处可依，删掉即退化**。故该节整节恢复常驻；画布文字预算这类在 `drawing.md` §6 有唯一真相源副本的条目可留可不留（静态检查另有兜底）
- **合成/分解的构造本身是一类证据**（实测：手倒立撑球题画了 N/f/mg 与合矢量 F，却没有正交分解的分量；而判据 `2Ncosθ=mg`、`f≤μN` 正住在分解与算式两层）。规则：推导用哪种构造（力三角形 / 正交分解 / 合矢量+摩擦锥），画面上**只出现那一种**——只画原始力、或同时叠两种画法都不算；合成结果有讲解需要时进 hud
- `讲解点` 成为 §3/§4/§5/§6 与 §7 自检项 4 共用的 leading word（定义在 §3 一次，四处复用）
- §5 补一条窄化：讲**力 / 加速度 / 速度变化**的讲解点，证据取画布矢量；讲**趋势或转折**的，证据取曲线——否则"至少一条投影可见证据"会被读数值满足（实测两轮生成都缺受力矢量）
- `check_demo` 静态检查新增 `evidenceCheck`（warning 级）：`chart-no-title`（图表定义数 > title 数）、`hud-overflow`（hud > 4 项）、`no-evidence`（既无矢量又无图表）。语义绑定（哪个讲解点配哪条证据）无法机械化，仍靠 §7 自检
- §7 自检项 4 的判据由"状态与判决量可见"升级为"逐个讲解点核对证据可指认且落在投影可见面内"，这是本轮唯一加重的自检 demand
- 未采纳的 lib 扩展（`marks` / 纯颜色键 / hud 随 seg 切换）留待需要时再评估；一旦实施，应把本 ADR 中被规避的措辞换回直接要求
- 提示词因此增加约 500 字符常驻负载；若后续把 §7 机制块 disclose 到独立文件（见评审建议），可抵消

## 修订（2026-10-04）：图清单行字段收敛，缺行核对工具化

随 ADR-0010（单源化）与 ADR-0007 两笔落盘的修订：

- §3 的行规格由「推导元素 / 表示 / 服务讲解点 / **通道** / **已落盘**」收敛为「**推导元素 / 表示 / 服务讲解点**」——"通道"归 §5（`通道分配` 那一步的产物），"已落盘"不是每行要手写的字段，而是 `check_demo` 的核对结果。
- §7 的「图清单逐行清零」由人工扫代码改为把清单按 `{kind,text}` 传给 `check_demo` 的 `drawList`，工具按行报缺——本文"图清单是'要画什么'的唯一真相源"不变，改的只是核对手段。
- 图清单仍只在 §3 生成一次；§5 只做通道与取值分配（ADR-0006 原设计的两遍保留，因为通道依赖 §5 的 hud 超编取舍）。

## 修订（2026-10-05）：图清单改由演示轮生成（§3 → §5）

随 ADR-0005 的 S1/S2 切分，**图清单从 §3（解题轮）移到 §5（演示轮）**：它是"结论 → 画面"的投影产物，属 S2；放在解题轮等于把投影工作提前进解题段。

- §3 只保留 **讲解点** 的定义（解题轮的导出物：每个阶段结论与每个选项判决各算一个讲解点）；
- §5 的「产出图清单」由**冻结结论**逐行生成（推导元素 / 表示 / 服务讲解点 / 承载通道），再接原来的通道与取值分配；
- §7 的 `drawList` 引用随之改为「§5 图清单」。

原设计（本文 Consequences 首条）的两次遍历仍然成立：§5 生成 + 定通道、§7 用 `check_demo` 核对缺行；变的只是清单的**生成时点**。
