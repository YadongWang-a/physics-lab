# 落地分段 + 核对关口：早写可运行页，用实测替代读源码

§7 由"一次写完整页 → 最后自检"改为**边分析边落地**：① **§1 之后**就建文件（命名 + 模板填空，骨架逐行保留、内容只进 `@slot`）→ **可运行的空页面**，此后每一步都用 `edit` **增量补 `@slot`**，不重写整页 ② **§2 之后**把元素与位置关系落位成画布上的基本物理模型 ③ **§3 推导之后**补解析卡（`.mpop` 三节：问题 → 推导 `#verdict` → 答案 `#ans`）④ **对答案通过后**按 §4/§5/§6 补齐 seg / hud 与矢量 / 图表（`title` 写明讲解点），并用 `check_demo` 修到 `ok=true`。

最后是**核对关口**（§4/§5/§6 与 §2 元素位置、§3 推导答案逐条对齐，不一致**改页面不改推导**）与语法 / ID 检查。

## 修订（同日，第三次）：建文件的锚点提前到 §1 之后

第二次把锚点放在"§2 之后"，实测（16:35 真机）机制生效但**首个画面仍在 send 后 504 s（8.4 min）**——模型把 §2/§3 想完才落笔，第 1 轮反而从 6.6 min 涨到 9.5 min。可见性瓶颈不是闸门，而是"第一笔落得太晚"。

因此锚点再前移一格：**§1 一结束就建文件**（此时只需要题目 → 名字 → 骨架，不依赖任何物理判断），后续全部变成 `edit` 增量。预期首个画面从 8.4 min 压到 1–2 min 量级，且总输出量不变（骨架本来就要写一次，只是提前；后续用 diff 而非重写）。

## 修订（同日，第二次）：把落地提前到分析轮

初版把落地写成"**对答案通过后开始**"，实测结果是：整个分析轮不产生文件——预览里从头到尾什么都没有，直到老师回答之后才开始写（真机 16:02 那次：第 1 轮 6.6 min 零工具调用、零文件）。这与"边分析边落地、老师边听边看到画面"的目标直接冲突，故改为交错形态：已定的部分先落盘，提问照常先问，用户回复后接着往下落。

**Status**: accepted

**Considered Options**:
- **不早写，只把 check_demo 写进规则**（"拿不准时用 check_demo 实测"）—— 已实测否决：两轮真实生成 `check_demo` 调用数为 0，lib 源码探测反而升到 27 次（64%）。模型没有可跑的东西，验证就不便宜，于是回到读源码
- **把落地放在"对答案"闸门之前** —— 否决：老师要多等两分钟才被问到答案；答案一变，写进解析卡的推导要返工。落地仍在用户回复后的那一轮
- **把 §7 自检项拆成五、六项** —— 否决：与 `check_demo` 的四项契约对齐更值钱；改为把"物理自审"与"讲解点证据"合成**核对**一项，并把它排在语法检查之前（原顺序里语法检查在第二项）
- **保留"定向读 `lib/*.js`"作为兜底** —— 否决（见 ADR-0003 修订第三次实测）：`limit≤60` 成了绕过拦截的常规手段，模型 14–21 次分段读把它当成了默认工作方式
- **五段落地（每段后各跑一次 `check_demo`）** —— 实测否决：模型并不分段写，而是在静默 4 分 41 秒后**一次 `write` 输出整页**，随后 7 次 `edit` + 8 次 `read` 修补成品（该文件被触碰 17 次，还撞了一次 `edits[0] and edits[1] overlap` 报错重试）；五个 `check_demo` 闸门 **0/4 触发**。分段落地只增加了自触碰成本，没换来"边写边验"

**Consequences**:
- **实测（16:02 真机，同题两轮）**：第 1 轮（分析+推导+提问）**6.6 min、0 次工具调用**（纯模型输出）；第 2 轮（落地）**9.2 min、24 次工具调用**（`edit 7` + 自读 8 + `ls 3`…）。`common.js` 命中 **0** ✓（硬墙生效）、`INDEX.md` 读 1 次 ✓、但 `check_demo` **0 次**。产物自检 `ok=true issues=0`
- 因此把落地压成两步并删掉逐段闸门：闸门既然不触发，其文字就是 no-op（按裁剪纪律删除）；`check_demo` 只保留一次（第 2 步末尾），应用层 `autoCheckDemo` 仍是兜底
- §5 的「讲解点证据表」同时轻量化（只列 讲解点 / 证据 / 承载通道，不再要求写计算式与矢量画法）——第 1 轮的输出量是那 6.6 分钟的主要来源
- 两步落地的第一步必须可运行——模板骨架本就"复制即可运行"，且 `.charts-row`/`.mpop` 允许留空，故不引入新的模板要求
- **可见性代价（需知）**：预览只在文件落盘后才刷新，而"写出正页"是一次大 `write`（11KB 级输出），所以老师看到的是"静默一段时间后整页出现 + 随后若干次修补"，不是逐块生长。要真做到逐块可见，需要让模型先只写骨架——那会把一次大输出拆成两次，与省轮数相冲突
- 核对关口规定"不一致**改页面, 不改推导**"：推导在 §3 已被用户确认，页面必须向它对齐
