# 物理演示 HTML 写作约定（CONVENTIONS）

本文件是物理演示 HTML 的**唯一写作规范**。写任何 HTML 之前，必须先读本文件与工作目录下**任意一个现有示例**（如 `arc-projectile.html`），以现有示例为模板，以本文件为规则。

本文件由 physics-lab 桌面应用随工作目录自动复制，**只读，严禁修改**（改动以应用随附版本为准，见 ADR 0012）。

## 0. 范围与只读边界

- 你正在生成/编辑的是**一个**物理演示 HTML 文件（称为目标文件）。
- **`lib/common.css`、`lib/common.js` 与本 CONVENTIONS.md 是共享公共库，严禁修改**；其它演示 HTML 也不得修改。
- 写文件必须通过 `write_demo`（整文件写）或 `edit_demo`（局部修改）工具（主进程自动校验，不合规会被拦截）；`validate_demo` 可随时自检。不要用其他方式写文件。
- 界面文字用中文；物理符号用 Unicode 下标（如 `v₀`、`θ`）或 `<code>` 标注。
- 演示分**动态**与**静态**两种形态，由你根据题目判断（见 §4 清单⑧）：
  - **动态演示**：时间演化类（运动、过程），运行/暂停/重置 + 动画。
  - **静态演示**：平衡、受力分析、几何关系类，**没有时间轴**——参数驱动即时重绘（拖滑块 → 画布立即更新），不加运行/动画。
- 每个页面 `<head>` 必须声明形态：`<meta name="demo-mode" content="dynamic">` 或 `content="static"`。缺声明会被验证器判为不合规。

## 1. 页面骨架（全部必填）

- **第一行**必须是 `<!-- physics-demo: 中文标题 -->`（应用据此识别文件、显示在文件树，见 ADR 0005）
- `<!DOCTYPE html>`，`<html lang="zh-CN">`；`<head>` 内**必须**有 `<link rel="stylesheet" href="lib/common.css">` 与形态声明 `<meta name="demo-mode" content="dynamic|static">`；需要公式时引入 `<script src="lib/mathjax.js" defer></script>`
- **浅色唯一**：不要写 `[data-theme]`、不要 🌙 主题切换按钮、不要主题切换 JS（见 ADR 0006）。页面专用 CSS 变量直接用浅色值。
- **演示模式监听器**：`<head>` 内必须内嵌以下监听器（见 ADR 0007），应用经 postMessage 触发演示态 reflow：
```html
<script>
window.addEventListener("message", function(e){
  var d=e.data; if(!d||d.cmd!=="present")return;
  document.body.classList.toggle("present", !!d.value);
});
</script>
```
- 主体结构：`<div class="wrap">`
  - 标题行 `.head-row`：`<h1>`（中文标题）+ `.sub`（物理摘要，含 `<code>` 公式）
  - 顶栏 `.topbar`："临界状态 ▶" + 各临界按钮（需时）+ 回到起点按钮
  - 双列 `.grid`（2.8fr 1fr，`@media(max-width:1100px)` 单列）：
    - 场景卡片 `.card`：`scene-actions` 按钮组（`#run` ▶ / `#pause` ⏸ / `#reset` ↺，**仅动态形态**）、`<canvas id="scene" height="430">`、图例条 `.legendbar`（矢量开关，两种形态均可用）、阶段标签 `#phase`（动态用）
    - 参数卡片 `.card`：`参数调整`（滑块组 `.ctl`，label+range+number）、`实时读数`（`.readouts` 的 `.ro`）、公式卡片 `.formulas`（可省）
  - 页脚 `.foot`：物理要点 + "双击此 HTML 即可在浏览器离线运行"（动态可加 "· 空格暂停 / R 重置"）
- 页尾**必须**有 `<script src="lib/common.js"></script>` + 内联 `<script>` 实现物理与绘制

## 2. lib/common.js 接口（必须用，不得重写）

| 函数 | 用途 |
|---|---|
| `$('id')` | 取元素 |
| `fitCanvas(c)` | 画布 DPI/高度适配，返回 `{ctx,w,h}`；监听 `resize` 重建 |
| `bindRangeNumber(rId, nId, parse, onChange)` | 滑块↔数字框双向绑定 |
| `setupLegend('legendBar', S.show, render)` | 图例开关（`.lg-item` 的 `data-k`） |
| `setupKeyboard(S, resetFn)` | 空格暂停/运行、R 重置（状态对象需有 `running`、`last`） |
| `startAnimation(frame)` | rAF 主循环启动 |
| `clamp(v,a,b)` | 数值夹取 |

## 3. 物理与动画约定

**动态形态**：
- 状态集中在一个对象 `S`（物理参数、位置、速度、时间、`running`、`last`、图例开关 `show`）。
- **子步积分**：主循环里 `dt=Math.min(dt,0.05)*S.speed`，再切成小步（如 0.002s）循环 `step()`；宁可步长小、不可数值炸。
- 提供"临界状态"按钮组：每个按钮对应一个可解析推导的关键状态（如最低点、平衡点、落地点），点击即跳到该状态；不可达的状态要标注原因。
- 能量守恒的演示要有能量显示（动能/势能条）。

**动态形态·受力分析**（过程涉及 ≥2 个力时强制；单力运动学可选）：
- 主画布默认叠加力矢量：每个力用箭头画在作用点（跟随物体），带标签与数值（如 `kx=12.3N`）；各力可用图例开关（`setupLegend` 的 `show` 对象）单独控制显隐。
- 独立 FBD（free-body diagram）面板：场景卡片下方加一个 FBD 卡片，默认折叠（`display:none`）；图例里加一个"受力图"开关，打开时展开面板、关闭时收起。
- FBD 内容：孤立隔离体（研究对象，不画场景/轨迹）+ 当前时刻全部外力矢量（带数值）。不画分量分解、不画合力——保持纯隔离受力图。
- 两层图例独立：现有的单力开关（如 `g`/`kx`）控制主画布叠加；"受力图"开关控制 FBD 面板显隐。

**动态形态·多阶段多体**（过程含多个时间阶段、多个研究对象时；单阶段单物不适用）：
- **阶段条**：画面上方一条阶段条，显示当前阶段名 + 时间轴进度（如 `施力加速 ████░░ 撤力减速 ░░ 绳绷直`）；运行时自动推进，阶段切换时高亮变化。临界状态按钮即各阶段（① 施力加速 ② 撤力减速 ③ 绳绷直 ④ 绳绷直后），点击定点跳转到该阶段起点；两者结合——阶段条给全局时序叙事，按钮给定点细看。
- **阶段切换自动暂停**：每个阶段切换时**自动暂停**动画，等用户点"继续"再推进下一阶段（让用户消化"为什么受力变了"再进入下一阶段）。动画速度默认更慢（如 0.3），让单阶段内的速度演化可看清。
- **相对运动可视化**：每个物块留一条轨迹线（不同颜色，随时间累积，看趋势）；读数面板加"两物间距""相对速度"两项（看精确值，间距增大->绳绷直瞬间相对速度归零）。
- **绳/连接可视化**：若物块间有绳/杆等连接，把连接画出来并随状态变化——松弛时下垂（弧线）、绷直时拉直（直线），状态变化一目了然。
- **每物块独立力矢量**：每个物块画自己受到的全部力（摩擦力方向随相对速度变、施力阶段额外的外力 F、绳绷直后的张力），跟随物块移动、带数值；配合 FBD 面板（隔离体详图）与图例开关控密度。阶段切换时力矢量随之变化是核心——这正是"体现加速过程"的关键。
- 单阶段单物题（自由落体、平抛）不需要这套；是否做多阶段由 agent 按题目判定（与形态判定同理）。

**静态形态**（平衡/受力分析，无时间轴）：
- 不写 `startAnimation`、`setupKeyboard`、运行/暂停/重置按钮、动画速度滑块——**没有动画**。
- 滑块 `bindRangeNumber` 的 onChange 回调里**立即重绘**画布与读数（参数驱动）。
- 受力分析是核心：每个力用箭头绘制（起点在作用点），带标签与数值（如 `T₁=8.77N`）；矢量可按力分别开关（图例）。
- 读数面板显示平衡条件验证值（如 ΣFₓ、ΣF_y 或判定结果"平衡/不平衡"）。
- 平衡态随参数变化的位置要即时重算；无平衡的参数区间要在读数和公式卡片中标注原因。

**静态形态·多状态**（同一装置的多个关键构型，如"绳拉直未挂 m₂"→"挂 m₂ 后平衡"）：
- 顶部用状态切换器：一排状态标签（即临界状态按钮，复用 `.topbar` + `setState` 机制），点哪个画布就显示那个构型。状态切换器是临界状态在静态演示里的形态——动态演示的临界状态是时间点，静态的是构型，同一套按钮。
- **瞬时切换**：点状态标签直接显示该稳态，**不画过渡过程**（静态演示分析的是平衡态，过渡属动态问题）。
- **参数全集恒显**：参数面板列出所有状态涉及的参数；当前状态用不到的滑块**置灰禁用**（`<input disabled>` + 灰色样式），面板布局恒定不重排。
- 单状态静态演示（简单受力分析）不需要状态切换器；是否做多状态由题目需求决定。

**共同约定**：
- 物理量用真实单位（米/秒/秒²/牛/焦耳）；`g=9.81 m/s²` 是默认值。
- 实时读数面板显示关键量，带单位。
- 关键公式写在公式卡片里，用 Unicode 下标与 `<code>`。

**几何写实**（所有形态都必须，硬规则）：
- **承载关系**：物体画在承载面上，不飘空——物块贴在传送带/地面/斜面上表面；球与弧面/轨道接触；弹簧两端分别连着物体和固定端。坐标计算时物体的底部（或接触点）必须落在承载面曲线上，不能凭感觉抬高。
- **连接关系**：绳/杆两端连着正确的物体（端点坐标对齐到物体）；绳绕过滑轮时与滑轮圆弧相切；绳长度符合约束——松弛时下垂（弧线）、绷直时拉直（直线），几何形态与物理状态对应。

## 4. 物理自检清单（每轮写完后**逐条报告**）

每次写完或改完，必须在回复中逐条核对并报告：

8. **动静判定说明**：回复开头一句话说明本题按**动态**还是**静态**处理及理由；页面 `<meta name="demo-mode">` 声明与此一致。

**动态形态**：

1. **单位一致**：所有物理量单位统一（m/s、m/s²、N、J）；g=9.81 m/s²。
2. **公式正确**：每个公式可独立推导（能量守恒、运动学、受力分析）；写出的式子与代码实现一致。
3. **守恒成立**：无耗散时总能（动能+势能）在动画中恒定；有能量损失要明确标注机制。
4. **临界状态可达**：每个临界状态按钮在当前参数范围内真实可达；不可达的要说明并给出理论位置。
5. **边界条件**：落地/接触/回弹判定正确，不会穿透地面或负时间。
6. **数值稳定**：最小步长下速度、位移不发散；刚度大时仍稳定。
7. **参数合理**：滑块范围与默认值教学友好，默认值下演示效果最佳。
8. **几何写实**：物体贴在承载面上（不飘空）、连接两端坐标对齐（绳绕滑轮相切、绳松弛下垂/绷直拉直）。逐个核对承载与连接关系。

**静态形态**：

1. **单位一致**：同动态；力用 N，质量 kg，长度 m。
2. **公式正确**：每个平衡方程（ΣF=0、Στ=0）可独立推导；写出的式子与代码实现一致。
3. **静力平衡验证**：逐力核对分量——水平/竖直方向的 ΣF 与代码计算一致；有力矩时 Στ=0 成立。
4. **平衡存在性**：指出平衡态存在/唯一/无解的参数区间；无解区间明确标注原因（如绳松弛、几何不可达）。
5. **约束与临界**：摩擦/接触临界（刚好滑动、刚好翻倒）条件正确；几何约束成立（绳不松弛、杆不穿透、角度范围合理）；物体贴承载面不飘空、连接两端坐标对齐。
6. **重绘正确性**：参数任意拖动不出现除零、NaN 或图形跳变；退化分支（如竖直绳 cosθ=0）单独处理。
7. **参数合理**：滑块范围与默认值教学友好，默认值下展示典型平衡态。

## 5. 文件命名

- 目标文件名为小写 kebab-case 英文物理名词（如 `arc-projectile.html`、`ball-spring.html`），不带数字序号。
- 第一行必须带 `<!-- physics-demo: 中文标题 -->` 标记（见 §1）。
- 生成模式下由你命名；编辑模式只写目标文件。若用户要求改名，通过 `write_demo` 写新文件名即可，系统会自动迁移会话。
